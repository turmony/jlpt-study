# 阅读器事件监测和持久缓存设计

用户已批准执行第5项；在现有稳定目录完成，不提交或推送任何文件，不删除已有 stash。

## 目标和约束

- 正常模式使用 watchdog 文件事件，500ms 稳定窗口合并连续保存；每60秒全量内容/Git/配置复核。异常时每1秒轮询并尝试恢复通知。
- 监测可发布的 Markdown、JSONL、图片、题源证据、目录移动、Git提交状态及配置/模板/展示资源；忽略读取事件、隐藏资料、外部链接、缓存和 Git 对象。
- 监测线程与构建回调分离；构建期间保留事件，不并行构建，不漏掉首次构建期间的编辑。失败保留上次成功站点并延后重试。
- 缓存放在 XDG_CACHE_HOME/jlpt-reader（默认 ~/.cache/jlpt-reader），按源目录和配置隔离。验证输入内容、Git状态、程序/依赖/展示配置与缓存输出完整性后复用；有效变化用已有增量构建；不兼容或损坏则全量重建。
- 只保存已验证成功的输出；原子切换缓存指针。缓存输出复制到本次临时会话后才发布，不在被缓存或发布的文件上就地构建。
- 每个项目最多2个成功版本；所有项目缓存文件数据预算3GiB（含候选）。同一项目当前已拥有的缓存文件，经实际内容校验与新输出一致后，可在候选缓存中以硬链接共享；容量按不重复的文件数据计数。禁止把学习资料或已发布会话文件作为硬链接来源；恢复会话仍复制独立文件。启动、更新完成及运行中每60分钟自动清理；保留各项目当前成功版本，只删除本程序标记且未使用的版本/残留，禁止越界或跟随符号链接及Windows目录联接。无法在预算内更新则跳过缓存，阅读器继续正常运行。
- 学习资料、Git历史和复习记录只读；保留试卷已有受限提交行为。缓存删除不影响学习数据。无缓存首次构建仍全量，不承诺未经验证的性能提升。

## 验证

真实通知/60秒复核/异常回退/构建期间保存/Git-only commit/配置编辑/相同mtime和大小编辑；缓存重复启动、输入及输出损坏、升级、容量限制、并发使用、中断残留和符号链接；完整pytest、JS测试、实际资料图片校验及至少5次性能测量（空闲10分钟）。

实际资料生成的单个站点约2.1GiB，完整复制候选与保留旧版会超过3GiB预算，因此实施时增加缓存生成文件共享；需验证大资源不重复占用、删除某个版本不影响其余版本、私有恢复副本隔离、旧共享资源损坏和硬链接不可用时保留已有缓存。
